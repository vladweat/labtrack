# API

Runtime API имеет префикс `/api/v1` и реализован в одном FastAPI приложении. В локальном окружении интерактивная схема доступна по `/docs`.

| Группа | Примеры задач |
|---|---|
| `/auth` | `POST /auth/token` и `GET /auth/me` |
| `/organizations`, `/samples` | Справочные данные и пробирки |
| `/shipments` | Shipment, manifest, pickup, delivery, incident и receiving |
| `/courier` | Снимок для офлайн-работы и синхронизация команд |
| `/operations`, `/analytics` | Скоупированные зависшие кейсы и агрегаты |
| `/notifications` | Inbox пользователя и отметка прочтения |

Все endpoints требуют текущую авторизацию там, где это необходимо; роль проверяется вместе с областью ресурса. Команды изменения состояния используют идемпотентность и серверные транзакции. Нормальная и офлайн-команда используют общий механизм перехода состояния.

## OpenAPI

Файл [`openapi/labtrack-v1.json`](../openapi/labtrack-v1.json) — черновик спецификации v0.6.1, а не полная схема runtime API. В нем есть устаревший маршрут авторизации `/auth/login`; фактический backend использует `/auth/token`. Не предполагайте паритет статического JSON со всеми реализованными endpoint или схемами. Для запущенного приложения ориентируйтесь на `/docs` и код маршрутов.

Нормативные требования вынесены в [API & Operations v0.6.1](24-api-and-operations-v061.md); они не заменяют runtime-контракт. Обзор backend приведен в [архитектуре](architecture.md).
